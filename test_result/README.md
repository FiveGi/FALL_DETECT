# ผลทดสอบ / Test results

โฟลเดอร์นี้เก็บ**ผลการทดสอบกับคลิปจริงใน `Test/`** ซึ่งเป็นฟุตเทจจริงชุดเดียวในโปรเจกต์นี้
ที่ไม่ใช่ชุดข้อมูลแล็บ ทุกไฟล์ในนี้**สร้างจากสคริปต์** ไม่ได้พิมพ์มือ

This folder holds the results of running the real `Test/` clips through the detector. Every
file here is generated; none of it is typed by hand.

## ไฟล์ในโฟลเดอร์

| ไฟล์ | คืออะไร |
|---|---|
| `test_clips.md` | ตารางผล อ่านอันนี้ |
| `test_clips.csv` | ตารางเดิม เปิดใน Excel ได้ (มี BOM ให้ Excel อ่านภาษาไทยถูก) |
| `test_clips.json` | ข้อมูลดิบต่อคลิป — จำนวนครั้งที่แจ้งเตือน และคะแนนสูงสุด |

## สร้างใหม่

```bash
python training/measure/testclips_current.py
```

รันซ้ำได้ ถ้าไฟล์ json มีคลิปไหนแล้วจะข้ามคลิปนั้น ถ้าต้องการวัดใหม่หมดให้ลบ json ก่อน

เทียบโมเดลตัวใหม่กับตัวที่ใช้งานอยู่ ใส่คอลัมน์เพิ่มในไฟล์เดิม:

```bash
TEST_MODEL_DIR=<โฟลเดอร์ที่มี fall_classifier_v3.onnx> TEST_LABEL="frame position" \
    python training/measure/testclips_current.py
```

## `incidents/` — งานตัดคลิปรวมให้ให้คะแนนได้

`Test/1`–`12` ตอนนี้ให้คะแนนไม่ได้เพราะไม่มี ground truth ต่อเหตุการณ์ ทั้งที่เป็น**ฟุตเทจจริงก้อนใหญ่ที่สุด
ที่โปรเจกต์นี้มี** — ประมาณ 3 เท่าของคลิปล้มเดี่ยว 4 คลิปที่ใช้ให้คะแนนอยู่

`python training/measure/cut_compilations.py` ตัดตามรอยต่อฉาก (hard cut) ได้ **112 ช่วง**
พร้อม contact sheet ช่วงละ 6 เฟรมใน `incidents/sheets/` เพื่อให้**ดูด้วยตาได้**

⚠️ **ยังไม่ใช่ ground truth** ทุก `label` ใน `incidents.json` เป็น `null` และต้องเป็น null
จนกว่าจะมีคนดูภาพจริง — รอยต่อฉากไม่เท่ากับเหตุการณ์ เหตุการณ์เดียวอาจกินสองฉาก
ฉากหนึ่งอาจไม่มีอะไรเลย และ end card ของ TikTok ก็นับเป็นฉากเหมือนกัน

5 คลิป (`2`, `3`, `6`, `10`, `11`) ตัดได้ไม่เกิน 2 ช่วง — เป็นคลิปถ่ายต่อเนื่องช็อตเดียว ไม่ใช่คลิปรวม

**สถานะตอนนี้: 126 ช่วง ยาวกลาง ~4 วินาที มี 63 ช่วง (50%) ที่ระบบแจ้งเตือน**

ตัวเลขนี้สำคัญเพราะพอติดป้ายเสร็จจะได้ทั้งสองด้าน — 63 ช่วงที่ยิงบอก**ความแม่น**
(ยิงแล้วถูกกี่ครั้ง) และ 63 ช่วงที่เงียบบอก**ความครบ** (มีล้มที่พลาดไปไหม)
เทียบกับตอนนี้ที่ให้คะแนนได้แค่ 4 คลิป

### รอยต่อฉากเคยตัดพลาดในคลิปมืด และแก้แล้ว

ตอนแรกได้ 112 ช่วง แต่พอเปิดดูภาพจริงเจอว่า `9.mp4` ช่วงหนึ่ง**มีสองฉากคนละเรื่องรวมอยู่ในช่วงเดียว**
(กล้องหน้าบ้าน กับกล้องกริ่งประตู) เพราะตัวตรวจรอยต่อใช้เกณฑ์ตายตัว 45 แต่รอยต่อจริงตรงนั้นวัดได้ 37.1
ขณะที่เฟรมข้างเคียงอยู่ที่ 1.0 — **โดดกว่าเพื่อนบ้าน 37 เท่า แต่ยังไม่ถึงเกณฑ์**

แก้โดยให้ถือเป็นรอยต่อถ้า**สูงกว่าค่ากลางของเฟรมรอบๆ มากๆ** ด้วย ไม่ใช่แค่เกินเลขตายตัว
ใช้ "หรือ" ไม่ใช่ "และ" เพราะสองความผิดพลาดไม่เท่ากัน — ตัดเกินแค่ทำให้เหตุการณ์เดียวกลายเป็นสองช่วง
ซึ่งคนรีวิวเห็นแล้วก็แค่นั้น แต่**ตัดขาดทำให้สองเหตุการณ์กลายเป็นหนึ่ง แล้วพิษไปทั้งชุดข้อมูลแบบเงียบๆ**

หลังแก้ได้ 126 ช่วง คำตอบเดิมที่ขอบเขตไม่เปลี่ยนถูกยกมา 15 จาก 22 อัน ที่เหลือทิ้งเพราะ
เป็นคำตอบของคลิปที่ไม่มีอยู่แล้ว

### กติกาติดป้าย: ต้องตรงกันสองทาง

`record_eye.py` เขียนคำตัดสินจากการ**ดูภาพเอง** ลงช่อง `by_eye` แล้ว `label` จะถูกตั้ง
**เฉพาะตอนที่ Gemini กับการดูเองตรงกัน** ถ้าขัดกันจะบันทึกไว้ในช่อง `conflict` และ `label` ยังเป็น null

**`unclear` เป็นคำตอบที่ถูกต้อง** หลายช่วงเป็นภาพกลางคืนที่ 6 เฟรมตัดสินไม่ได้จริงๆ
การเดาตรงนั้นแย่กว่าการเว้นว่าง — ช่องว่างมีคนกลับมาดู แต่ป้ายผิดจะถูกเอาไปวัดตลอดไป

### ความคืบหน้า

| | |
|---|---|
| Gemini ตอบแล้ว | 34/126 |
| ดูภาพเองแล้ว | 18 (ในนั้น `unclear` 2) |
| **ตรงกันสองทาง → ติดป้ายแล้ว** | **13** |

13 ช่วงที่ติดป้ายแล้วเป็นช่วงที่ระบบแจ้งเตือนทั้งหมด — 10 ช่วงอยู่ในขอบเขตและ**เป็นการล้มจริงทั้ง 10**
อีก 3 ช่วงอยู่นอกขอบเขต (เด็ก, ถนนสาธารณะพร้อมกราฟิกข่าวทับจอ)

⚠️ **ห้ามอ่าน 10/10 เป็นความแม่นยำ** เพราะเพิ่งติดป้ายได้ 13 จาก 63 ช่วงที่แจ้งเตือน และยังไม่ได้แตะ
63 ช่วงที่เงียบเลย ซึ่งเป็นครึ่งที่บอกว่าพลาดอะไรไป ตัวเลขนี้เป็นแค่ความคืบหน้า ไม่ใช่ผล

**ที่ขัดกันทั้งสองครั้งเป็นเรื่องเดียวกัน คือนิยามของ "นอกขอบเขต"** — Gemini ตีกว้าง
(ลิฟต์, ห่วงบาสล้มทับ) ส่วนการดูเองตีแคบ (นับเฉพาะภาพที่ระบบนี้ไม่มีวันได้เจอ เช่น การ์ตูน กีฬา เด็ก)
เป็นความไม่ลงรอยเชิงระบบ ไม่ใช่ความบังเอิญ ต้องนิยามให้ชัดก่อนติดป้ายต่อ

## อ่านตัวเลขให้ถูก

**`13`–`16` มีล้มจริงคลิปละ 1 ครั้ง** จึงตัดสินได้ว่าจับได้หรือพลาด

**`17` ไม่มีการล้มเลย** เป็นกลุ่มคนเต้นออกกำลังกายกลางลาน เงียบคือคำตอบที่ถูก — เคยถูกนับเป็น
"คลิปที่ทุกค่าพลาด" อยู่หลายวัน ซึ่งทำให้ตัวที่ใช้งานอยู่ดูแย่กว่าความจริง

**`1`–`12` เป็นคลิปรวมหลายเหตุการณ์** ไม่มี ground truth ต่อเหตุการณ์ จึง**นับจำนวนครั้งเท่านั้น
ห้ามอ่านเป็นความแม่นยำ** เพราะตัวส่วนไม่มีอยู่จริง เทียบระหว่างคอลัมน์ได้ แต่เทียบกับ 100% ไม่ได้

**`10` กับ `11` เป็นเด็ก** ถ่ายไกลและถ่ายกลางคืน อยู่นอกขอบเขตที่ระบบนี้ทำ

**`13` คือคลิปเดียวที่ค่าที่ใช้งานอยู่ยังพลาด** กล้องเคลื่อนและซูม (background flow 4.8 px/frame
เทียบกับ 0.03 ของคลิปกล้องนิ่ง) คนหนุ่ม และจบลงที่ท่าคลาน ไม่มีอะไรในไปป์ไลน์นี้ออกแบบมา
สำหรับกล้องเคลื่อน — เป็นข้อจำกัดที่รู้ตัว ไม่ใช่บั๊กที่ยังไม่แก้
