## Further required corrections

3. **P1 — stale requests and unmount recreate refresh loops.** `MediaViewer.vue:182–190,213` guards only camera id/overlay. Two requests for the same pair, resolved newest then oldest, leave the older URL installed and **two timers** active. Calling the exact unmount callback while a request is pending still allows its completion to schedule another timer. URL/useStreamApi changes and A→B→A also evade that guard by inspection. 4. **P1 — 600-second limit is not enforced before disclosure.** `app/services/media_token.py:96–100` checks time **after yielding**. An underlying iterator returning its first frame at t=601 delivers that frame past deadline=600 (reproduced); an iterator that never yields cannot be interrupted by this wrapper. `app/services/stream_service.py:405–422` can keep waiting without yielding while active with no frame. Put deadline/cancellation checks in the producer/wait path and before each yield, with bounded waits. Evidence: Python command above, fake monotonic clock; generator close was observed after iteration. No real 600-second stream or indefinitely stalled camera was run.

5. **P2 — log redaction is incomplete.** `media_token.py:108–127` matches raw `t=` only; Flask accepts `?%74=probe` as `t=probe`, but the filter leaves it in the request log (reproduced). Filters attach only to three logger names, not application/error handlers or external proxies. More directly, `MediaViewer.vue:338–342` emits the token-bearing URL and `MonitorView.vue:625–627` writes it to console on terminal failure; executing both actual bodies reproduces disclosure. Redact structured URL query keys after decoding and sanitize frontend events/logs; validate each configured proxy/error sink. Ten minutes of backend output with zero tokens does not establish coverage. Evidence: both commands above; external proxy/error telemetry not exercised.

6. **P1 dependency — revocation is fail-open on errors.** `app/models/token_blocklist.py:18–25` catches lookup errors and returns False; this is used by `media_token.verify` at `:85` and issuance's JWT callback at `app/__init__.py:199–207` (which also catches errors and returns False). Executing the actual method with a failing query returns “not revoked.” This dependency predates the diff but invalidates unconditional revocation claims. If subsequent user/camera reads succeed, revoked credentials are not rejected; a total database outage may instead cause those reads to fail, so this is not a claim that every DB outage grants access. `app/routes/auth.py:117–119` also ignores the blacklist write's failure return and reports successful logout (static). Fail closed on revocation read/write failures and add endpoint-level fault injection; the latter was not run.
